# Техническое задание: Универсальный конвертер документов `markoff`

## 1. Общие сведения и назначение проекта

* **Наименование проекта:** `markoff`
* **Язык разработки:** Rust (актуальная стабильная версия / Rust 2024–2026 edition)
* **Назначение:** Кроссплатформенная утилита с графическим интерфейсом (GUI) и полнофункциональным интерфейсом командной строки (CLI) для двунаправленной конвертации (биективного преобразования) документов форматов Microsoft Office (DOCX, XLSX, PPTX) в разметку Markdown / форматы структурированных данных (CSV, JSON, YAML, TOML) и обратно.
* **Лицензия:** MIT / Apache-2.0.

---

## 2. Архитектура и структура проекта

Проект строится по принципу модульного монорепозитория (**Cargo Workspace**) для строгого разделения бизнес-логики, CLI и GUI:

```text
markoff/
├── Cargo.toml                  # Корневой манифест воркспейса
├── README.md                   # Документация и интерактивный Roadmap/Progress
├── crates/
│   ├── markoff_core/           # Ядро: парсеры, промежуточный AST, движок конвертации
│   │   ├── Cargo.toml
│   │   └── src/
│   ├── markoff_cli/            # CLI-интерфейс (clap v4+)
│   │   ├── Cargo.toml
│   │   └── src/
│   └── markoff_gui/            # GUI-интерфейс (eframe/egui v0.36+, glow/wgpu бэкенды)
│       ├── Cargo.toml
│       └── src/
├── tests/                      # Интеграционные e2e-тесты (round-trip)
└── build.rs                    # Скрипт сборки с интеграцией vergen v10+

```

## 3. Технологический стек и зависимости

Все зависимости фиксируются на актуальных мажорных версиях:

1. **Базовый рантайм и метаданные сборки:**
* `vergen` (v10.0+), `vergen-gitcl`, `vergen-cargo` — генерация метаданных сборки (commit SHA, branch, rustc semver, timestamp, target triple) для флагов CLI `--version` и диалогового окна «О программе» в GUI.
* `thiserror` (v2.0+) и `anyhow` — типизированные ошибки ядра и контекстные ошибки бинарных крейтов.
* `tracing` и `tracing-subscriber` — структурированное логирование с фильтрацией уровней (`trace`, `debug`, `info`, `warn`, `error`).


2. **Интерфейс командной строки (CLI):**
* `clap` (v4.5+, features: `derive`, `cargo`, `env`) — декларативный парсинг аргументов, автогенерация справки и shell completions.
* `indicatif` — индикаторы прогресса (progress bars/spinners) при пакетной обработке.


3. **Графический интерфейс (GUI):**
* `egui` (v0.36+) и `eframe` (v0.36+).
* **Рендереры и условная компиляция:**
* **Windows:** Графический бэкенд `glow` (OpenGL) с конфигурацией `eframe` (`features = ["glow", "default_fonts"]`).
* **Linux:** Графический бэкенд `wgpu` (WebGPU / Vulkan / Wayland) (`features = ["wgpu", "wayland", "x11"]`).
* Инициализация `NativeOptions` через атрибуты `#[cfg(target_os = "...")]` для выбора целевого бэкенда при запуске.


* `egui_extras` — расширенные интерактивные таблицы (`TableBuilder`), поддержка кэширования и изображений.
* `rfd` (Native File Dialogs) — асинхронный выбор файлов/директорий.


4. **Парсинг и сериализация данных:**
* **Office formats:** `docx-rs`, `calamine` (высокопроизводительное чтение XLSX/XLS/ODS), `rust_xlsxwriter` / `umya-spreadsheet` (запись и форматирование XLSX), работа с пакетами OOXML через `quick-xml` и `zip`.
* **Markdown & AST:** `pulldown-cmark` (с поддержкой GFM-таблиц, сносок, задач), `comrak` / кастомный AST-транслятор.
* **Data formats:** `serde`, `serde_json`, `csv`, `serde_yaml` (или `yaml-rust2`), `toml`.

## 4. Функциональные требования

### 4.1. Матрица поддерживаемых направлений конвертации

| Исходный формат | Целевой формат | Поддерживаемые элементы / Особенности |
| --- | --- | --- |
| **DOCX** | **Markdown (CommonMark + GFM)** | Заголовки (H1–H6), списки (нумерованные/маркированные), inline-стили (жирный, курсив, зачеркнутый), гиперссылки, таблицы, блоки кода, извлечение изображений, сноски. |
| **Markdown** | **DOCX** | Генерация стилей параграфов, таблиц, списков, кода, с возможностью подключения базового шаблона `.dotx`. |
| **XLSX** | **Markdown Tables** | Преобразование каждого листа (Sheet) в отдельную Markdown-таблицу или единый документ с иерархией разделов. |
| **Markdown Tables** | **XLSX** | Генерация книги Excel с автоподбором ширины колонок, заморозкой строки заголовков (freeze panes) и базовым выравниванием. |
| **JSON / CSV / YAML / TOML** | **XLSX** | Сериализация структурированных списков/массивов объектов в плоские или многостраничные таблицы Excel с сохранением типов ячеек (числа, даты, булевы значения, строки). |
| **XLSX** | **JSON / CSV / YAML / TOML** | Парсинг страниц книги Excel в структурированные данные (автоопределение заголовков, конвертация типов, экспорт в один или несколько файлов). |
| **PPTX ⇄ Markdown** | *(Extensible)* | Экспорт текстового содержимого слайдов в Markdown (слайд = разделитель `---` / заголовок H2) и генерация презентаций из Markdown-структур. |

### 4.2. Требования к CLI (`markoff`)

* **Команды и флаги:**
* `markoff convert <INPUT> [-o <OUTPUT>] [--from <FMT>] [--to <FMT>]` — одиночная конвертация с автоматическим определением формата по расширению.
* `markoff batch <DIR> --pattern "*.docx" --to md -o <OUT_DIR>` — пакетная конвертация файлов с выводом progress bar.
* `markoff --version` / `-V` — вывод расширенной информации о сборке от `vergen` (Commit SHA, Target triple, Build Date, Rustc version).
* `markoff gui` — запуск графической оболочки (или запуск без аргументов по умолчанию).
* Поддержка потокового ввода/вывода (stdin/stdout) для текстовых форматов (Markdown, CSV, JSON, YAML, TOML).



### 4.3. Требования к GUI (`egui` v0.36+)

* **Интерфейс и UX:**
* Современный дизайн с поддержкой Dark/Light тем.
* **Drag-and-Drop:** Перетаскивание одного или нескольких файлов напрямую в окно программы.
* **Двухоконный режим (Split View):**
* Левая панель: Предпросмотр исходного файла или редактор Markdown / JSON / YAML с подсветкой синтаксиса.
* Правая панель: Живой предпросмотр результата конвертации (рендеринг Markdown или интерактивная таблица `egui_extras::TableBuilder` для табличных данных).


* **Настройки конвертации:** Выбор разделителей CSV, параметров форматирования Markdown-таблиц, путей сохранения извлеченных медиафайлов.
* **Пакетный менеджер задач:** Таблица очереди конвертации со статусами (`Pending`, `In Progress`, `Success`, `Failed`), прогресс-барами и кнопками быстрого открытия папки с результатом.
* **Окно «О программе»:** Полная визуализация метаданных `vergen`, используемого графического бэкенда (`glow` на Windows / `wgpu` на Linux) и системной информации.

## 5. Стандарты качества, тестирование и документация

### 5.1. Документация кода (rustdoc)

* 100% покрытие публичного API крейта `markoff_core` документационными комментариями (`///`, `//!`).
* Обязательное наличие раздела `# Examples` с исполняемыми доктестами (`cargo test --doc`) для всех ключевых структур и функций.
* Наличие разделов `# Errors` и `# Panics` у публичных методов согласно Rust API Guidelines.

### 5.2. Тестирование

1. **Unit-тесты:** Изолированное тестирование трансформации каждого узла AST (парсинг тегов OOXML, форматирование строк Markdown, валидация типов ячеек).
2. **Интеграционные тесты (E2E):** Тестирование биективности (Round-trip testing):
* `DOCX -> Markdown -> DOCX` (проверка семантической эквивалентности).
* `XLSX -> JSON/CSV -> XLSX` (проверка совпадения числовых данных и типов).


3. **Property-based тестирование:** Использование `proptest` / `quickcheck` для генерации произвольных структур данных и валидации устойчивости парсеров к некорректным входным данным.
4. **Бенчмарки:** Интеграция `criterion` для отслеживания производительности парсинга и генерации больших документов и таблиц (10 000+ строк).

### 5.3. Проверка качества и линтинг (CI/CD Quality Gates)

* **Форматирование:** `cargo fmt --all -- --check`.
* **Статический анализ:** `cargo clippy --all-targets --all-features -- -D warnings` (zero-warnings policy, включение педантичных линтов `clippy::pedantic`).
* **Аудит безопасности:** `cargo audit` и `cargo deny` (проверка уязвимостей в зависимостях и совместимости лицензий).
