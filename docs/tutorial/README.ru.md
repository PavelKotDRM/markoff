# Руководство по использованию готового приложения markoff

Это руководство предназначено для пользователя, который получил уже собранное
приложение `markoff` и хочет пользоваться им без установки Rust, Cargo или
Docker.

`markoff` — локальный конвертер документов и структурированных данных. В
готовом пакете есть два приложения:

- `markoff` — консольная версия для отдельных файлов, конвейеров и
  пакетной обработки;
- `markoff_gui` — графическая версия с очередью файлов и предварительным
  просмотром.

Файлы не отправляются во внешний сервис: преобразование выполняется локально.

## 1. Что находится в готовом пакете

Релизный пакет для Windows обычно распространяется как архив
`markoff-windows-x86_64.zip`, а пакет для Linux — как
`markoff-linux-x86_64.tar.gz`.

После распаковки в каталоге должны находиться следующие файлы:

| Платформа | Консольное приложение | Графическое приложение |
| --- | --- | --- |
| Windows | `markoff.exe` | `markoff_gui.exe` |
| Linux | `markoff` | `markoff_gui` |

Не переименовывайте файлы во время первого запуска, если хотите использовать
примеры из этого руководства без изменений. Приложение можно хранить в любом
каталоге, доступном текущему пользователю.

### Что не нужно устанавливать

Для обычного использования готовых бинарных файлов не требуются:

- Rust и Cargo;
- исходный код проекта;
- Docker;
- отдельная установка Pdfium.

Для GUI нужна графическая сессия операционной системы. В Linux это рабочая
сессия X11 или Wayland; запуск GUI на сервере без графического окружения не
сработает. Консольное приложение можно использовать на сервере или в
скриптах без GUI.

При первом преобразовании PDF приложение может подготовить встроенную
библиотеку Pdfium в кэше пользователя. Это может занять немного больше
времени, чем последующие преобразования. Сетевое подключение и отдельно
установленная Pdfium-библиотека во время работы не нужны.

## 2. Первый запуск

### Windows

1. Распакуйте архив, например в `C:\Apps\markoff`.
2. Откройте PowerShell в распакованном каталоге.
3. Проверьте версию консольного приложения:

   ```powershell
   .\markoff.exe --version
   ```

4. Чтобы открыть графическое приложение, запустите:

   ```powershell
   .\markoff_gui.exe
   ```

   Также GUI можно запустить командой:

   ```powershell
   .\markoff.exe gui
   ```

При запуске файла из другого каталога укажите полный путь. Если путь содержит
пробелы, в PowerShell используйте оператор вызова `&`:

```powershell
& "C:\Apps\markoff\markoff.exe" --version
& "C:\Apps\markoff\markoff_gui.exe"
```

### Linux

1. Распакуйте архив:

   ```bash
   tar -xzf markoff-linux-x86_64.tar.gz
   cd markoff-linux-x86_64
   ```

2. Проверьте версию:

   ```bash
   ./markoff --version
   ```

3. Запустите GUI:

   ```bash
   ./markoff_gui
   ```

   Альтернативный способ:

   ```bash
   ./markoff gui
   ```

Обычно архив сохраняет право на выполнение файлов. Если оно было потеряно
при копировании, восстановите его один раз:

```bash
chmod +x markoff markoff_gui
```

Чтобы запускать CLI из любого каталога, можно добавить каталог с бинарниками в
`PATH` или указывать путь к файлу явно:

```bash
/opt/markoff/markoff --version
```

## 3. Выбор интерфейса

Используйте **GUI**, если нужно:

- выбрать несколько файлов мышью;
- добавлять файлы перетаскиванием;
- видеть очередь заданий;
- просматривать исходный файл и результат;
- выполнять конвертацию по одному выбранному файлу.

Используйте **CLI**, если нужно:

- автоматизировать преобразование в скрипте;
- выбрать точный путь каждого результата;
- обработать каталог по шаблону;
- передавать данные через stdin/stdout;
- преобразовать Markdown, DOCX или JSON/YAML/TOML в PDF, а также использовать PDF как входной формат;
- работать без графического окружения.

GUI и CLI используют одно и то же ядро конвертации, поэтому правила форматов,
перезаписи и обработки ошибок у них одинаковые. Различается только способ
взаимодействия.

## 4. Использование CLI

В примерах для Windows используется `.\markoff.exe`, а для Linux —
`./markoff`. Если приложение было добавлено в `PATH`, имя можно заменить
на `markoff`.

### 4.1. Справка и версия

Получить общую справку:

```powershell
.\markoff.exe --help
```

Получить справку по отдельной команде:

```powershell
.\markoff.exe convert --help
.\markoff.exe batch --help
```

Проверить версию, commit и сведения о сборке:

```powershell
.\markoff.exe --version
```

Основные команды:

| Команда | Назначение |
| --- | --- |
| `convert` | Преобразовать один файл |
| `batch` | Преобразовать все подходящие файлы в каталоге |
| `gui` | Запустить графическое приложение |

Если запустить CLI без команды, приложение выведет подсказку. Для реальной
конвертации используйте `convert` или `batch`.

### 4.2. Преобразование одного файла

Общий синтаксис:

```text
markoff convert INPUT [--from FORMAT] [--to FORMAT] [-o OUTPUT]
                       [--overwrite] [--delimiter CHAR]
```

Для Windows подставьте `.\markoff.exe`, а для Linux — `./markoff`.

#### Самый короткий вариант

Формат источника определяется по расширению, а формат результата — по
параметру `--to`:

```powershell
.\markoff.exe convert .\report.csv --to md
```

Результат будет сохранён рядом с исходным файлом как `.\report.md`.

#### Явный путь к результату

```powershell
.\markoff.exe convert .\notes.md -o .\output\notes.docx
```

В этом случае формат результата определяется по расширению `docx`. Каталог
`.\output` будет создан автоматически, если его ещё нет.

Более наглядный вариант с явным `--to`:

```powershell
.\markoff.exe convert .\notes.md --to docx -o .\output\notes.docx
```

#### Как выбираются форматы

Правила определения форматов такие:

1. исходный формат берётся из расширения входного файла;
2. `--from` явно задаёт исходный формат и имеет приоритет над расширением;
3. целевой формат берётся из `--to`;
4. если `--to` не указан, целевой формат определяется по расширению `-o`;
5. если невозможно определить целевой формат ни одним способом, CLI завершится
   с ошибкой.

Например, файл с нестандартным именем можно преобразовать так:

```powershell
.\markoff.exe convert .\incoming.data --from json --to md -o .\incoming.md
```

Имена форматов нечувствительны к регистру. Поддерживаются псевдонимы
`md`/`markdown`, `xlsx`/`xlsm`, `yaml`/`yml` и `html`/`htm`.

#### Защита от перезаписи

По умолчанию существующий результат не перезаписывается. Это позволяет
безопасно повторно запускать команду:

```powershell
.\markoff.exe convert .\report.csv --to md
```

Если `report.md` уже существует, команда завершится ошибкой. Чтобы явно
разрешить перезапись, добавьте `--overwrite`:

```powershell
.\markoff.exe convert .\report.csv --to md --overwrite
```

В качестве альтернативы укажите новое имя или другой каталог результата.

### 4.3. Примеры преобразования

#### Word в Markdown

```powershell
.\markoff.exe convert .\report.docx --to md -o .\converted\report.md
```

#### PDF в Markdown и документы в PDF

```powershell
.\markoff.exe convert .\manual.pdf --to md -o .\converted\manual.md
```

PDF можно создать из Markdown, DOCX или JSON/YAML/TOML:

```powershell
.\markoff.exe convert .\notes.md -o .\notes.pdf
.\markoff.exe convert .\report.docx --to pdf
.\markoff.exe convert .\report.json --to pdf
```

PDF-экспорт сохраняет поддерживаемое форматирование, таблицы, код, ссылки,
сноски и растровые изображения PNG/JPEG/GIF/BMP/WebP. Заголовки формируют
оглавление в панели навигации PDF, а ссылки на разделы и HTTP(S)/mailto/tel
остаются кликабельными. Содержимое автоматически
перевёрстывается на страницы A4; точная разбивка и расположение элементов
исходного документа не сохраняются. PDF-вход поддерживается для документов со
встроенным текстовым слоем; для сканированного PDF потребуется OCR во внешнем
инструменте, так как встроенного OCR в `markoff` нет.

#### Markdown в DOCX

```powershell
.\markoff.exe convert .\notes.md -o .\notes.docx
```

#### CSV в Markdown с разделителем `;`

```powershell
.\markoff.exe convert .\export.csv --to md --delimiter ';'
```

#### CSV в XLSX

```powershell
.\markoff.exe convert .\export.csv --to xlsx -o .\workbooks\export.xlsx --delimiter ';'
```

#### JSON-массив объектов в XLSX

```powershell
.\markoff.exe convert .\people.json --to xlsx
```

Для этого сценария JSON должен быть массивом объектов, например:

```json
[
  { "name": "Ada", "active": true },
  { "name": "Grace", "active": false }
]
```

#### XLSX в JSON

```powershell
.\markoff.exe convert .\people.xlsx -o .\people.json
```

Если в книге несколько листов, результат содержит объект с именами листов.
Если лист один, результатом является массив строк-объектов.

#### HTML в Markdown

```powershell
.\markoff.exe convert .\page.html --to md
```

#### Презентация PPTX в Markdown

```powershell
.\markoff.exe convert .\slides.pptx --to md
```

#### Markdown в HTML или PPTX

```powershell
.\markoff.exe convert .\article.md -o .\article.html
.\markoff.exe convert .\slides.md -o .\slides.pptx
```

### 4.4. Стандартный ввод и вывод

Для текстовых форматов можно использовать `-` вместо пути:

- `-` как `INPUT` — читать из stdin;
- `-` после `-o` — писать в stdout.

Поддерживаются Markdown, JSON, CSV, YAML, TOML и HTML. Двоичные форматы
DOCX, ODT, XLSX/XLSM, ODS, PDF, PPTX и ODP нельзя передавать через stdin/stdout.

Пример для PowerShell:

```powershell
Get-Content -Raw .\data.json |
    .\markoff.exe convert - --from json --to yaml -o -
```

Пример для Linux:

```bash
cat ./data.json | ./markoff convert - --from json --to yaml -o -
```

При чтении из stdin параметр `--from` обязателен, потому что у входного потока
нет расширения. При записи в stdout параметр `--to` также рекомендуется
указывать явно:

```powershell
Get-Content -Raw .\table.csv |
    .\markoff.exe convert - --from csv --to md -o -
```

Потоковый режим удобен для конвейеров:

```powershell
Get-Content -Raw .\source.md |
    .\markoff.exe convert - --from md --to html -o .\result.html
```

### 4.5. Пакетная обработка

Общий синтаксис:

```text
markoff batch DIRECTORY --pattern GLOB --to FORMAT
                       -o OUTPUT_DIRECTORY
                       [--overwrite] [--delimiter CHAR]
```

Пример: преобразовать все DOCX из каталога `documents` в Markdown:

```powershell
.\markoff.exe batch .\documents --pattern '*.docx' --to md -o .\converted
```

Для каждого входного файла создаётся файл с тем же базовым именем в каталоге
`.\converted` с новым расширением.
Каталог результата создаётся автоматически.

Рекурсивный шаблон можно задать явно:

```powershell
.\markoff.exe batch .\documents --pattern '**\*.docx' --to md -o .\converted
```

В Linux используйте разделители пути текущей оболочки:

```bash
./markoff batch ./documents --pattern '*.docx' --to md -o ./converted
```

Полезные примеры:

```powershell
# CSV с разделителем ;
.\markoff.exe batch .\exports --pattern '*.csv' --to xlsx `
    -o .\workbooks --delimiter ';'

# Перезаписать уже существующие Markdown-файлы
.\markoff.exe batch .\documents --pattern '*.docx' --to md `
    -o .\converted --overwrite
```

Особенности `batch`:

- шаблон интерпретируется относительно переданного `DIRECTORY`;
- индикатор показывает число обработанных файлов;
- результаты записываются непосредственно в указанный выходной каталог;
- при совпадении базовых имён во входных подкаталогах возможен конфликт
  выходных имён;
- без `--overwrite` существующий результат вызывает ошибку;
- если один файл не поддерживается или повреждён, пакетная операция
  завершается ошибкой.

### 4.6. Разделитель CSV

По умолчанию используется запятая:

```powershell
.\markoff.exe convert .\comma.csv --to md
```

Для CSV с точкой с запятой:

```powershell
.\markoff.exe convert .\semicolon.csv --to md --delimiter ';'
```

Для TSV используется специальное значение `tab`:

```powershell
.\markoff.exe convert .\table.tsv --to md --delimiter tab
```

`--delimiter` принимает один ASCII-символ или слово `tab`. Параметр действует
и при `convert`, и при `batch`, в том числе в маршрутах через XLSX или DOCX.

## 5. Использование GUI

### 5.1. Запуск

Запустите `markoff_gui.exe` двойным щелчком или командой:

```powershell
.\markoff_gui.exe
```

В Linux:

```bash
./markoff_gui
```

На панели приложения используются английские подписи кнопок. Ниже приведены
их точные названия.

### 5.2. Полный сценарий конвертации

1. Нажмите **Add files** и выберите один или несколько файлов.
   Допустимо также перетащить файлы в окно: приложение принимает их в очередь
   при сбрасывании в любую область окна.
2. В панели **Queue** выберите файл, который нужно обработать.
3. В поле **Convert to:** выберите целевой формат.
4. Расширения выходных файлов в очереди обновляются автоматически при смене
   целевого формата.
5. При необходимости включите **Overwrite existing files**, если нужно
   заменить уже существующий результат. Входной файл при этом не перезаписывается.
6. Для поддерживаемого обмена документа с JSON/YAML/TOML при необходимости
   включите **Tables only**, чтобы оставить в результате только табличные
   блоки. При несовместимой паре форматов переключатель отключён.
7. Для CSV установите один символ в поле **CSV delimiter:**. По умолчанию
   используется `,`; для обычного CSV с разделителем `;` укажите `;`.
8. Для PDF, HTML, DOCX или ODT при необходимости нажмите
   **Style → Choose...** и выберите TOML-тему или **Style → New...**, чтобы
   сохранить шаблон со значениями по умолчанию. Кнопка **Preview** открывает
   предварительный просмотр темы, а **Clear** возвращает стандартное оформление.
9. Нажмите **Convert selected**.
10. В центральной области переключайтесь между вкладками **Source** и
   **Result**, чтобы просмотреть исходное содержимое и результат.

Файл сохраняется рядом с исходным. Например, для
`C:\Docs\report.csv` и цели Markdown результатом будет
`C:\Docs\report.md`. В GUI нельзя выбрать отдельный выходной каталог для
конкретного задания; если нужен другой каталог или точное имя, используйте
CLI.

Один и тот же путь нельзя добавить в очередь дважды. Преобразование выполняется
для одной выбранной записи за раз.

### 5.3. Что доступно в GUI

В списке **Convert to:** доступны:

- Markdown;
- PDF;
- DOCX;
- JSON;
- CSV;
- YAML;
- TOML;
- XLSX;
- HTML;
- PPTX.

DOCX доступен в GUI как целевой формат. Выберите **docx** в поле
**Convert to:**, а затем **Convert selected**.
Результат сохранится рядом с исходным файлом с расширением `.docx`.

PDF можно выбрать как целевой формат для Markdown, DOCX и JSON/YAML/TOML.
Выберите **pdf** в поле **Convert to:**, затем
**Convert selected**. Полученный PDF можно просмотреть во вкладке **Result**.
PDF также можно добавить как входной файл; для отсканированного PDF без
текстового слоя потребуется OCR во внешнем инструменте.

```powershell
.\markoff.exe convert .\manual.pdf --to md
```

В GUI доступны также:

- **Light** / **Dark** — переключение светлой и тёмной темы;
- **About** — версия, commit, ветка, время сборки, целевая платформа и
  используемый графический renderer.

### 5.4. Управление стилями и предварительный просмотр темы

Дополнительная тема оформления поддерживается для выходных форматов PDF, HTML,
DOCX и ODT. Она необязательна: если файл темы не выбран и `--style` не указан,
Markoff использует прежнее встроенное оформление выбранного формата.

В GUI:

1. Выберите PDF, HTML, DOCX или ODT в поле **Convert to:**.
2. Нажмите **Choose...** рядом с полем **Style:**.
3. Выберите файл с расширением `.toml`.
4. Окно **Style preview** откроется автоматически.
5. После изменения TOML-файла нажмите **Preview**, чтобы перечитать его с диска.
6. Нажмите **Clear**, чтобы отключить тему и вернуться к стандартному оформлению.

#### Создание шаблона темы со значениями по умолчанию

Чтобы не писать тему с нуля, создайте шаблон, в котором перечислены все
параметры с их значениями по умолчанию и комментариями:

- в GUI нажмите **Export template...** на панели инструментов. Кнопка
  доступна при любом целевом формате: она только сохраняет файл шаблона и
  показывает под панелью путь к нему (или причину ошибки), не меняя выбранную
  тему;
- в GUI для PDF, HTML, DOCX или ODT можно также нажать **Style → New...**:
  шаблон сохраняется, сразу выбирается как текущая тема и открывается в
  **Style preview**;
- в CLI выполните:

```powershell
.\markoff.exe style-template -o .\corporate.toml
.\markoff.exe style-template -o .\corporate.toml --overwrite
```

Без `-o` (или с `-o -`) шаблон выводится в stdout. Для сохранения в файл
используйте `-o`: перенаправление `>` в Windows PowerShell 5 записывает UTF-16,
а тема должна быть в UTF-8. Существующий файл
заменяется только с `--overwrite`; диалог сохранения GUI сам запрашивает
подтверждение замены.

Откройте файл в редакторе, измените нужные значения и нажмите **Preview**, чтобы
увидеть результат. Строки, которые не нужны, можно удалить: пропущенные
параметры получают те же значения по умолчанию. Эти значения относятся к
теме; без выбранной темы каждый формат по-прежнему использует своё встроенное
оформление (например, PDF без темы использует более крупные заголовки).

Окно **Style preview** показывает:

- размер и ориентацию страницы, поля, верхний и нижний колонтитулы
  (`{page}`/`{pages}` подставляются как пример номеров);
- заголовки уровней 1–6 с размерами, цветами по уровням, жирностью и курсивом;
- основной текст с выравниванием, отступом первой строки, ссылкой и
  inline-кодом;
- цитату с цветом, фоном, полосой слева, отступом и курсивом;
- маркированный список с заданным маркером и отступом уровня;
- блок кода с размером, цветом текста, фоном и внутренним отступом;
- таблицу с заголовком, границами, отступами ячеек и чередованием строк;
- горизонтальную линию, размер текста сносок и ограничение ширины изображений;
- таблицу всех вычисленных значений темы.

GUI использует собственные шрифты для отрисовки окна, поэтому названия
`font_family`, `headings.font_family` и `code.font_family` показываются как
параметры, но не загружают произвольный системный шрифт в само окно. Эти
семейства применяются в создаваемых HTML, DOCX и ODT. PDF использует
комплектные Unicode-шрифты, но применяет все остальные параметры темы.

Ту же тему можно передать через CLI:

```powershell
.\markoff.exe convert .\report.md --to pdf --style .\corporate.toml
.\markoff.exe batch .\documents --pattern "*.md" --to docx `
  --output .\converted --style .\corporate.toml
```

Полный пример находится в
[`docs/examples/style-theme.toml`](../examples/style-theme.toml).

#### Структура TOML-темы

Ниже фрагмент примера; полный список ключей со значениями по умолчанию выводит
`markoff style-template`.

```toml
[document]
font_family = "Aptos"
font_size_pt = 11
text_align = "justify"
first_line_indent_pt = 14

[headings]
level_colors = ["#1F4E79", "#1F4E79", "#2E75B6", "#2E75B6", "#404040", "#404040"]
sizes_pt = [26, 20, 16, 14, 12, 11]

[page]
size = "A4"
orientation = "portrait"
footer_text = "Page {page} of {pages}"

[blockquote]
background = "#F3F6F9"
border_color = "#2E75B6"
italic = true

[table]
stripe_background = "#F7FAFC"
```

| Секция | Параметр | Значение (по умолчанию) |
| --- | --- | --- |
| `document` | `font_family` | Семейство основного шрифта (`Calibri`) |
| `document` | `font_size_pt` | Размер основного текста, > 0 (`11`) |
| `document` | `text_color` | Цвет текста `#RRGGBB` (`#000000`) |
| `document` | `paragraph_spacing_before_pt` | Интервал перед абзацем, ≥ 0 (`0`) |
| `document` | `paragraph_spacing_after_pt` | Интервал после абзаца, ≥ 0 (`8`) |
| `document` | `line_height` | Множитель высоты строки, > 0 (`1.2`) |
| `document` | `text_align` | `left`, `center`, `right` или `justify` (`left`) |
| `document` | `first_line_indent_pt` | Отступ первой строки обычного абзаца, ≥ 0 (`0`) |
| `headings` | `font_family` | Семейство шрифта заголовков (`Calibri`) |
| `headings` | `color` | Цвет всех уровней (`#1F4E79`) |
| `headings` | `level_colors` | Необязательно: шесть цветов H1–H6, заменяют `color` |
| `headings` | `sizes_pt` | Ровно шесть размеров H1–H6 (`[16, 14, 12, 11, 10, 9]`) |
| `headings` | `spacing_before_pt` / `spacing_after_pt` | Интервалы вокруг заголовка (`10` / `6`) |
| `headings` | `bold` / `italic` | Жирность и курсив (`true` / `false`) |
| `page` | `size` | `A3`, `A4`, `A5`, `Letter` или `Legal` (`A4`) |
| `page` | `orientation` | `portrait` или `landscape` (`portrait`) |
| `page` | `margin_top_pt`, `margin_right_pt`, `margin_bottom_pt`, `margin_left_pt` | Поля страницы (`42`) |
| `page` | `header_text` / `footer_text` | Текст колонтитулов, `{page}` — номер, `{pages}` — число страниц (пусто) |
| `page` | `header_footer_font_size_pt` | Размер текста колонтитулов (`9`) |
| `links` | `color` / `underline` | Цвет и подчёркивание ссылок (`#0563C1` / `true`) |
| `blockquote` | `text_color` | Цвет текста цитаты (`#404040`) |
| `blockquote` | `background` | Фон цитаты или `none` (`none`) |
| `blockquote` | `border_color` / `border_width_pt` | Полоса слева (`#B3B3B3` / `1.5`) |
| `blockquote` | `indent_pt` / `italic` | Отступ и курсив (`14` / `false`) |
| `lists` | `indent_pt` | Отступ каждого уровня вложенности (`18`) |
| `lists` | `bullet` | Маркер ненумерованного списка, 1–4 символа (`•`) |
| `code` | `font_family` | Моноширинный шрифт (`Consolas`) |
| `code` | `font_size_pt` / `text_color` | Размер и цвет кода (`9.5` / `#333333`) |
| `code` | `background` | Фон блока кода (`#F6F8FA`) |
| `code` | `inline_background` | Фон inline-кода или `none` (`#F6F8FA`) |
| `code` | `padding_pt` | Внутренний отступ блока кода (`7`) |
| `table` | `font_size_pt` | Размер текста таблицы (`9.5`) |
| `table` | `header_background` / `header_color` | Фон и цвет строки заголовка (`#EBF0F6` / `#000000`) |
| `table` | `border_color` / `border_width_pt` | Границы ячеек (`#B4BCC6` / `0.5`) |
| `table` | `cell_padding_pt` | Отступ текста от границы ячейки (`4`) |
| `table` | `stripe_background` | Фон каждой второй строки тела или `none` (`none`) |
| `horizontal_rule` | `color` / `width_pt` | Цвет и толщина линии `---` (`#B4BCC6` / `0.7`) |
| `footnotes` | `font_size_pt` | Размер текста сносок (`9`) |
| `images` | `max_width_percent` | Максимальная ширина изображения, 1–100 % ширины текста (`100`) |

Ограничения форматов:

- `images.max_width_percent` действует в PDF и HTML: DOCX и ODT, создаваемые
  Markoff, не встраивают изображения;
- в HTML размер страницы, поля и колонтитулы задаются через CSS `@page` и
  видны при печати или сохранении в PDF из браузера;
- в DOCX и ODT `{page}`/`{pages}` становятся полями номера страницы и числа
  страниц, которые обновляет текстовый редактор.

Все секции и параметры необязательны. Неуказанные параметры получают
стандартные значения. Неизвестное имя параметра, цвет не в формате `#RRGGBB`,
пустое имя шрифта, отрицательный интервал или неположительный размер приводят
к явной ошибке. Ошибка также отображается в окне **Style preview**.

### 5.5. Статусы очереди и предварительный просмотр документа

В очереди отображаются имя файла и статус:

- **Pending** — файл добавлен, но ещё не преобразован;
- **Success** — преобразование завершено, путь к результату отображается
  в сообщении задания;
- **Failed** — преобразование завершилось ошибкой, текст ошибки отображается
  в результате и сообщении задания.

Предпросмотр выбирается для текущей записи очереди:

- Markdown отображается с форматированием;
- JSON, YAML и TOML отображаются как сворачиваемое дерево;
- другие поддерживаемые типы показываются как текст или в доступном для
  приложения представлении.

### 6.3. Два режима для JSON, YAML и TOML

Эти форматы используются в двух разных сценариях.

#### Документный режим

При преобразовании Markdown, DOCX, PDF, PPTX или HTML в JSON/YAML/TOML
сохраняется структура документа в виде упорядоченного массива `blocks`.
Блоки содержат типизированный `content`: текст, выделение, код, ссылки,
сноски, закладки, переносы строк и изображения. Списки сохраняют порядок,
вложенность и начальные номера; для ограждённых блоков кода хранится строка
параметров `info`. Старые JSON/YAML/TOML-документы с полями `text` и `rows`
по-прежнему принимаются.

Например, элементы таблицы и встроенное форматирование представлены
структурированными узлами, а не плоским текстом:

```json
{
  "blocks": [
    {
      "type": "heading",
      "level": 1,
      "content": [{ "type": "text", "text": "Report" }]
    },
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "A " },
        {
          "type": "strong",
          "content": [{ "type": "text", "text": "bold" }]
        },
        { "type": "text", "text": " paragraph." }
      ]
    },
    {
      "type": "table",
      "cells": [
        [
          [{ "type": "text", "text": "Name" }],
          [{ "type": "text", "text": "Score" }]
        ],
        [
          [{ "type": "text", "text": "Ada" }],
          [{ "type": "text", "text": "42" }]
        ]
      ]
    }
  ]
}
```

Такой файл можно преобразовать обратно:

```powershell
.\markoff.exe convert .\report.md -o .\report.json
.\markoff.exe convert .\report.json -o .\restored.md

# Сохранить в JSON только таблицы из DOCX и восстановить только их в DOCX
.\markoff.exe convert .\report.docx --to json --tables-only
.\markoff.exe convert .\report.json --to docx --tables-only
```

Определения сносок хранятся отдельными блоками `footnote_definition`, а
ссылки на них — узлами `footnote_reference`. Преобразование JSON/YAML/TOML
между собой сохраняет эту схему. По умолчанию преобразование в Markdown,
DOCX, PPTX или HTML восстанавливает поддерживаемые блоки и inline-элементы.
Флаг `--tables-only` оставляет табличные блоки при обмене документами и
JSON/YAML/TOML.

#### Табличный режим

При преобразовании JSON/YAML/TOML в XLSX входные данные должны быть массивом
объектов. Ключи объектов становятся заголовками столбцов, а значения —
ячейками.

```json
[
  { "id": 1, "name": "Ada" },
  { "id": 2, "name": "Grace" }
]
```

Не передавайте в табличный маршрут произвольный одиночный объект или массив
скалярных значений: приложение ожидает именно массив объектов.
Этот существующий маршрут JSON/YAML/TOML ↔ XLSX остаётся отдельным от режима
документной структуры: XLSX-маршрут уже работает только с таблицами, поэтому
флаг `--tables-only` к нему не применяется.

### 6.4. Таблицы Markdown и книги Excel

При преобразовании Markdown в XLSX:

- каждая таблица становится листом;
- заголовок второго уровня `## Sheet name` задаёт имя листа;
- первая строка таблицы используется как строка заголовков;
- ширина столбцов подстраивается под содержимое;
- строка заголовков закрепляется.

При обратном преобразовании XLSX в Markdown листы представлены отдельными
таблицами.

## 7. Практические сценарии

### 7.1. Конвертация отчёта Word с сохранением изображений

1. Создайте каталог результата.
2. Запустите:

   ```powershell
   .\markoff.exe convert .\report.docx --to md `
       -o .\converted\report.md
   ```

3. Откройте `.\converted\report.md`.
4. Если в документе были поддерживаемые встроенные изображения, рядом с
   Markdown будет создан каталог `.\converted\image`. Не удаляйте его, если
   изображения должны отображаться в Markdown.

### 7.2. Подготовка Excel-книги из CSV

Для CSV с разделителем `;`:

```powershell
.\markoff.exe convert .\sales.csv --to xlsx `
    -o .\reports\sales.xlsx --delimiter ';'
```

Результат можно открыть в Excel или преобразовать обратно в CSV/JSON:

```powershell
.\markoff.exe convert .\reports\sales.xlsx -o .\reports\sales.json
```

### 7.3. Преобразование Markdown-документа в Word

```powershell
.\markoff.exe convert .\specification.md `
    -o .\deliverables\specification.docx
```

Перед передачей файла проверьте, что исходный Markdown содержит нужные
заголовки, списки и таблицы. Сложная верстка, отсутствующая в поддерживаемой
модели документа, не будет восстановлена автоматически.

При преобразовании в DOCX:

- заголовки Markdown получают стили Word `Heading 1`–`Heading 6`;
- таблицы сохраняются как таблицы Word с сеткой и выделенной строкой заголовка;
- ссылки Markdown становятся активными гиперссылками, включая ссылки на
  разделы документа.

### 7.4. Пакетная обработка документов

```powershell
.\markoff.exe batch .\incoming --pattern '*.docx' --to md `
    -o .\converted
```

После завершения проверьте количество файлов в `.\converted`. Если в исходных
подкаталогах встречаются одинаковые имена, обработайте их отдельными
командами или задайте шаблоны без конфликтов: `batch` использует базовое имя
файла и не сохраняет структуру исходных подкаталогов в имени результата.

### 7.5. Конвейер JSON в YAML

```powershell
Get-Content -Raw .\config.json |
    .\markoff.exe convert - --from json --to yaml -o .\config.yaml
```

Если нужно только вывести результат на экран:

```powershell
Get-Content -Raw .\config.json |
    .\markoff.exe convert - --from json --to yaml -o -
```

### 7.6. Обработка презентации

```powershell
.\markoff.exe convert .\presentation.pptx --to md `
    -o .\text\presentation.md
```

Такой результат удобен для извлечения заголовков и текста слайдов. Он не
является точной копией визуального макета презентации.

## 8. Как обрабатываются изображения и структура документов

### Изображения в DOCX и PDF

При выводе в Markdown поддерживаемые встроенные растровые изображения
извлекаются в каталог `image` рядом с Markdown-файлом и подключаются ссылками
вида `![описание](image/image1.png)`.

При выводе документной структуры в JSON/YAML/TOML изображения сохраняются
внутри данных в формате base64. Такой результат не зависит от внешних файлов.

Растровые изображения Markdown, DOCX и документных схем JSON/YAML/TOML
встраиваются в PDF. В неподдерживаемом формате изображения преобразование
завершится явной ошибкой; изображения без встроенных данных выводятся
альтернативным текстом.

При обратном преобразовании JSON/YAML/TOML или Markdown в Markdown приложение
может восстановить файлы изображений в каталоге `image`. При обратном
преобразовании Markdown в DOCX изображения пока не встраиваются обратно как
рисунки OOXML: ссылка на изображение может остаться обычным текстом.

### Сохранение форматирования

Обычно сохраняются:

- заголовки и абзацы;
- маркированные и нумерованные списки;
- таблицы;
- полужирный, курсивный, зачёркнутый и подчёркнутый текст;
- встроенный и ограждённый код;
- цитаты;
- горизонтальные линии;
- поддерживаемые сноски, закладки и ссылки `PAGEREF`.

Каждый отдельный список Markdown получает в DOCX собственную последовательность
нумерации; начальный номер нумерованного списка сохраняется. Пустая строка
между пунктами сама по себе не начинает новый список.

При конвертации результат следует проверить визуально, особенно перед
публикацией или передачей документа другому пользователю.

## 9. Ограничения

- PDF со встроенным текстовым слоем можно преобразовать в Markdown или
  документную схему JSON/YAML/TOML. PDF создаётся из Markdown, DOCX и
  JSON/YAML/TOML; результат содержит перевёрстанный текст, а не исходный
  макет и изображения.
- Для PDF без встроенного текстового слоя OCR не выполняется.
- Разметка страниц, векторная графика и таблицы PDF не восстанавливаются как
  исходный макет; изображения добавляются в Markdown отдельными ссылками.
- PPTX преобразуется по заголовкам слайдов и основному тексту/маркированным
  спискам. Для ODP видимый Markdown также является упрощённым представлением,
  однако полный исходный пакет сохраняется в служебном блоке Markoff.
- HTML преобразуется по смысловым элементам: заголовкам, тексту, ссылкам,
  изображениям, спискам, цитатам, блокам кода и таблицам. CSS, точный
  визуальный макет, формы и скрипты не сохраняются.
- ODT/ODS/ODP -> Markdown добавляет служебный блок с полным исходным пакетом.
  Без правок пакет восстанавливается побайтно; текстовые правки существующих
  элементов сохраняют формулы, стили, диаграммы, изображения, макеты, заметки,
  метаданные и расширения. Небезопасная структурная правка возвращает ошибку,
  а не документ с молча потерянными объектами.
- Сложный макет и изображения ODT/ODP не извлекаются в отдельные редактируемые
  Markdown-ресурсы и остаются внутри служебного блока.
- DOCX, ODT, XLSX/XLSM, ODS, PDF, PPTX и ODP нельзя использовать в потоковом режиме
  stdin/stdout.
- Для табличного преобразования JSON/YAML/TOML требуется массив объектов.

## 10. Ошибки и устранение проблем

### `output file already exists`

Файл назначения уже существует. Выберите другой путь либо явно разрешите
перезапись:

```powershell
.\markoff.exe convert .\input.md --to html `
    -o .\output.html --overwrite
```

В GUI включите **Overwrite existing files**.

### `stdin requires --from`

При использовании `-` в качестве входа добавьте исходный формат:

```powershell
Get-Content -Raw .\input.json |
    .\markoff.exe convert - --from json --to md -o -
```

### `specify --to or an output path with a known extension`

CLI не смог определить формат результата. Добавьте `--to` или укажите
расширение в `-o`:

```powershell
.\markoff.exe convert .\input.data --from json `
    --to yaml -o .\output.yaml
```

### `unsupported format`

Расширение файла не распознано. Проверьте расширение или задайте `--from` для
нестандартного имени входного файла. Для цели задайте `--to`.

### `conversion from ... to ... is not implemented yet`

Выбрано направление, которого нет в таблице поддерживаемых маршрутов.
Поменяйте целевой формат или разбейте операцию на поддерживаемые шаги. Не
переименовывайте расширение вручную: это не преобразует содержимое файла.

### Ошибка структуры данных

Если JSON/YAML/TOML преобразуется в XLSX, проверьте, что корневое значение —
массив объектов и что внутри нет смешанных скалярных элементов. Если
документный JSON/YAML/TOML не открывается, проверьте наличие массива `blocks`
и корректность сериализации.

### GUI не запускается в Linux

Проверьте, что:

1. у файла есть право на выполнение;
2. запущена графическая сессия X11 или Wayland;
3. доступны системные библиотеки выбранного графического окружения.

Если графическая среда недоступна, используйте `./markoff` для
конвертации через командную строку.

### В Markdown не отображаются изображения

Проверьте, что каталог `image` находится рядом с Markdown-файлом и что
относительные ссылки не были нарушены перемещением только одного файла.
Перемещайте Markdown вместе с каталогом `image`.

### Результат отличается от исходного документа

Проверьте раздел [Ограничения](#9-ограничения). `markoff` переносит
поддерживаемую структуру и содержание, но не обещает пиксельное совпадение
макета Office, PDF или презентации.

## 11. Краткая памятка

### Windows

```powershell
# Версия
.\markoff.exe --version

# Один файл
.\markoff.exe convert .\input.docx --to md -o .\output\input.md

# Пакетная обработка
.\markoff.exe batch .\documents --pattern '*.docx' --to md `
    -o .\converted

# GUI
.\markoff_gui.exe
```

### Linux

```bash
# Версия
./markoff --version

# Один файл
./markoff convert ./input.docx --to md -o ./output/input.md

# Пакетная обработка
./markoff batch ./documents --pattern '*.docx' --to md -o ./converted

# GUI
./markoff_gui
```

Перед массовой обработкой или включением `--overwrite` сначала выполните
пробную конвертацию на копии одного файла и проверьте результат.
